# 0004: TanStack Router with file-based routing

- **Status:** accepted
- **Date:** 2026-10-18

## Context

The platform is a React SPA built with Vite. We want typed routes, nested
layouts, and route-level code splitting without hand-maintaining a route
configuration.

## Decision

Use TanStack Router with the `@tanstack/router-plugin` Vite plugin and
file-based routing:

- Routes live in `apps/platform/src/routes/`.
- `routeTree.gen.ts` is generated by the plugin and committed.
- `autoCodeSplitting` is enabled so each route is its own chunk.

## Consequences

- Adding a page means adding a file; the route tree updates on save.
- `Link` targets and route params are type-checked.
- Generated code is part of the repo, so `typecheck` works on a fresh clone
  without running the dev server first. Regenerate with `vite build` or the dev
  server.
- Route filenames are part of the public URL structure and should be reviewed
  like API routes.
- The team must learn TanStack Router's conventions (`__root.tsx`, `$param`,
  layout routes) rather than React Router's.

## Alternatives considered

- **React Router** — familiar, but weaker type safety for links and search
  params.
- **TanStack Router with code-based routes** — more explicit, but requires
  editing a central route file for every page.
- **Next.js** — brings a server runtime and framework lock-in that this SPA does
  not need.
